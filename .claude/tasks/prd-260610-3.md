# PRD: InfluencerSeeder v3 — Resumable, Stealth, Config-driven Scraper

> v2(`prd-260610-2.md`)의 CSV 기반 6-step 스크래퍼를 토대로,
> **봇 탐지 회피 / 백그라운드 실행 / 중단-재개 / 설정 공유 / 플로우 최적화**를 추가한다.
> 이 문서는 v2 대비 **증분(delta)** 을 중심으로 기술한다. v2에서 그대로 유지되는 부분은 "v2 유지"로 표기.

---

## 1. 배경 & 문제 정의

| # | 원본 메모 | 해결할 문제 |
|---|----------|------------|
| 1 | 구글시트 연동은 개발이 어려워 CSV 파일 공유로 대체 | 외부 API 의존 제거, 설정/데이터를 파일로 주고받기 (**v2 유지**) |
| 2 | 인스타 버튼 위치값이 업데이트·OS·화면 크기에 따라 바뀌고 상대위치도 오류남 | 버튼 매핑을 **사용자가 직접·상세하게** 세팅하고 CSV로 공유 가능하게 |
| 3 | 켜놓고 다른 업무를 하고 싶음 | **백그라운드 실행** 지원 |
| 4 | 봇으로 걸리지 않게 하고 싶음 | 클릭마다 **랜덤 딜레이 + 브라우저 핑거프린트 랜덤화** |
| 5 | 웹이 아니라 설치형 프로그램이어야 함 | **네이티브 설치 패키지** 배포 (**v2 유지 — PyQt6**) |
| 6 | 설정을 5개 그룹으로 구성 | 웹/버튼매핑/시간텀/플로우/타겟 설정 분리 |
| 7 | 진행하다 만 것을 다시 진행 | 설정·데이터 CSV **불러오기 + 재개(resume)** |
| 8 | 수집 데이터 중복 없게 | username 기준 **dedup** |
| 9 | 프로필 위주로 저장 | **프로필 중심 스키마** |
| 10 | 중복이면 프로필 진입 플로우 생략 | **플로우 최적화 (조기 skip)** |
| 11 | 로그·진행상황을 꼼꼼하게 | **상세 로깅 + 영속 로그 파일** |

## 2. 설정 그룹 (5개)

UI의 SettingsView(QTabWidget)와 CSV 파일을 다음 5개 그룹으로 재편한다.

### 2.1 웹 설정 — `data/web.csv`
브라우저/세션 동작.
```
key,value
browser,chrome
headless,false               # true면 창 없이 백그라운드 수집 (§4)
window_width,1280            # 0이면 매 실행마다 랜덤 (§5)
window_height,900
randomize_window,true       # true면 window_width/height 무시하고 프리셋 중 랜덤
randomize_user_agent,true   # 실행마다 UA 풀에서 랜덤 선택 (§5)
user_data_dir,              # 비우면 임시 프로필, 채우면 로그인 세션 재사용
locale,ko-KR
implicit_wait,5
page_load_timeout,30
```

### 2.2 버튼매핑 설정 — `data/selectors.csv` (v2 확장)
**핵심 변경:** step 하나당 **여러 후보 셀렉터(fallback 체인)** 를 허용한다.
인스타 UI 변동·OS·화면 크기 차이를 사용자가 직접 메꿀 수 있게 한다.

```
step_id,step_name,priority,selector_type,selector_value
search_icon,돋보기 클릭(Step1),1,xpath,"//a[contains(@href,'/explore/')]//*[name()='svg' and @aria-label='검색']"
search_icon,돋보기 클릭(Step1),2,xpath,"//a[contains(@href,'/search')]"
search_icon,돋보기 클릭(Step1),3,css,"svg[aria-label='Search']"
search_input,검색 입력(Step2),1,xpath,"//input[@placeholder='검색']"
search_input,검색 입력(Step2),2,xpath,"//input[@placeholder='Search']"
tag_result,태그 클릭(Step3),1,xpath,"//a[contains(@href,'/explore/tags/')]"
post_link,이미지 클릭(Step4),1,xpath,"//a[contains(@href,'/p/')]"
profile_link,프로필 클릭(Step5),1,css,"header a[href]:not([href='/'])"
username_text,유저네임,1,css,"header h2, header h1"
followers_count,팔로워 수,1,xpath,"//a[contains(@href,'/followers/')]//span[@title]"
following_count,팔로우 수,1,xpath,"//a[contains(@href,'/following/')]//span"
posts_count,게시물 수,1,xpath,"//header//li[1]//span//span"
bio_text,소개글,1,css,"header section > div:last-child"
website_link,웹사이트,1,css,"header a[href*='http']:not([href*='instagram.com'])"
```

- `priority` 오름차순으로 시도, **처음 매칭되는 요소를 사용**. 모두 실패 시 해당 step 에러 로그 + (옵션) 좌표 폴백.
- 좌표 폴백: `selector_type = coord`, `selector_value = "x,y"` (절대 픽셀). 최후의 수단으로만, priority 가장 낮게.
- UI에서 행 추가/삭제/순서변경 가능. **[셀렉터 테스트]** 버튼: 현재 열린 브라우저에서 해당 셀렉터가 몇 개 매칭되는지 즉시 표시.

### 2.3 시간텀 설정 — `data/delays.csv` (v2 settings.csv에서 분리)
v2의 `stepN_delay_min/max` 를 별도 파일로 이동.
```
step_id,delay_min,delay_max
step1,1.0,2.5
step2,0.5,1.5
step3,2.0,4.0
step4,1.5,3.0
step5,2.0,4.0
step6,0.5,1.5
back,1.0,2.5
scroll,0.8,2.0       # 그리드 스크롤 간 딜레이
typing_char,0.05,0.18  # 검색어 한 글자씩 타이핑 시 글자당 딜레이 (사람처럼)
```

### 2.4 플로우 설정 — `data/flow.csv`
태그 순환·수집량 등 탐색 전략.
```
key,value
max_tags,3              # 태그 추천 목록에서 몇 번째까지 클릭하며 순환할지
tag_start_index,0       # 재개 시 시작 태그 인덱스
posts_per_tag,5         # 태그당 수집할 게시물 수
scroll_max_attempts,15  # 그리드에서 게시물 URL 모을 때 최대 스크롤 횟수
skip_visited_profile,true   # 이미 수집/제외된 username이면 Step5 진입 생략 (§6)
stop_on_consecutive_miss,10 # 연속 N회 수집 실패 시 조기 종료 (v2 MAX_MISS)
```

### 2.5 타겟 설정 — `data/target.csv`
필터 조건.
```
key,value
min_followers,0      # 0 = 하한 없음
max_followers,0      # 0 = 상한 없음
min_following,0
max_following,0
min_posts,0          # 최소 게시물 수
keyword,             # 해시태그 (# 제외)
mode,hashtag         # hashtag | caption(추후)
```

> **마이그레이션:** v2의 `settings.csv` 단일 파일을 `web/delays/flow/target` 4개로 분리.
> `storage.load_*()` 는 파일 없으면 기본값을 기록 후 반환(v2 동작 유지).

## 3. 데이터 스키마 (프로필 중심 + dedup)

### 3.1 `data/results.csv` — 프로필 1행 = 인플루언서 1명
```
username,full_name,followers,following,posts_count,bio,website,is_private,profile_url,source_tag,source_post_url,collected_at
```
- **PK = `username`** (소문자 정규화). 저장 전 `results.csv` + `excluded.csv` 와 대조해 **중복이면 append 안 함**.
- `source_post_url` = 이 프로필을 처음 발견한 게시물 (추적용, 프로필 자체는 1행만).
- `collected_at` = ISO8601 (`2026-06-10T13:20:00+09:00`).

### 3.2 `data/excluded.csv` — v2 유지
```
username
```

### 3.3 `data/state.json` — 재개용 진행 상태 (신규)
```json
{
  "keyword": "인턴",
  "tag_index": 1,
  "post_index": 3,
  "collected_count": 17,
  "seen_usernames": ["abc", "def"],
  "updated_at": "2026-06-10T13:20:00+09:00"
}
```
- 매 step 완료마다 갱신. 앱 재시작 시 **[이어하기]** 누르면 `tag_index/post_index` 부터 재개.
- `seen_usernames` 는 메모리 dedup 셋을 영속화(빠른 중복 판정).

## 4. 백그라운드 실행 (메모 #3)

- **headless 모드** (`web.csv:headless=true`): Chrome `--headless=new` 로 창 없이 수집.
  - 단, 인스타 로그인은 사용자가 직접 해야 하므로(크리덴셜 미저장) **첫 로그인은 headful → 이후 `user_data_dir` 세션 재사용 → headless 재실행** 흐름을 안내.
- **창 모드 + 트레이 최소화**: headful이어도 메인 윈도우는 시스템 트레이로 최소화 가능(`QSystemTrayIcon`). 수집은 별도 `QThread` 라서 UI를 최소화해도 계속 진행(이미 v2 구조상 동작).
- 수집 중 OS 절전 방지(옵션): macOS `caffeinate`, Windows `SetThreadExecutionState`.
- 수집 진행은 트레이 툴팁/알림으로도 표시.

## 5. 봇 탐지 회피 (메모 #4)

- **랜덤 딜레이**: 모든 step 사이 `delays.csv` 범위 내 `random.uniform` (v2 유지·확장).
- **사람같은 타이핑**: 검색어를 한 글자씩 `typing_char` 딜레이로 입력.
- **브라우저 핑거프린트 랜덤화** (`web.csv` 토글):
  - `randomize_user_agent`: UA 풀에서 실행마다 랜덤 선택.
  - `randomize_window`: 창 크기를 프리셋(`1280x900, 1440x900, 1366x768, 1536x864`) 중 랜덤.
  - `--disable-blink-features=AutomationControlled` + `navigator.webdriver` 제거 스크립트 주입.
- **랜덤 스크롤**: 그리드 스크롤량/딜레이를 매번 다르게.
- ⚠️ **명시적 한계**: 위 조치에도 인스타가 봇 판정/임시 차단할 수 있음을 UI 경고로 고지(원본 메모의 솔직한 단서 반영). 차단 감지 시(로그인 화면·챌린지 페이지로 리다이렉트) **즉시 일시정지 + 사용자 알림**.

## 6. 플로우 최적화 (메모 #8~10)

게시물 그리드 → 프로필 진입 사이에 **조기 dedup 게이트**:
```
Step4: 게시물 진입
  ↓
게시물 헤더에서 username 추출 (프로필 페이지 진입 전, 가능하면 그리드 단계에서)
  ↓
if username ∈ (results ∪ excluded ∪ seen_usernames):
      [SKIP] Step5(프로필 진입)·Step6(저장) 생략 → 로그 "중복 건너뜀" → 다음 게시물
  else:
      Step5 프로필 진입 → Step6 추출 → 필터(target.csv) 통과 시 저장 → seen에 추가
```
- 이로써 이미 본 사람의 프로필을 다시 여는 불필요한 네비게이션 제거 → 속도↑ + 탐지 위험↓.
- 필터 미통과(팔로워/게시물 수 미달)도 `seen_usernames` 에 넣어 재방문 방지.

## 7. 중단-재개 / 설정·데이터 공유 (메모 #7)

- **불러오기(Import)**: 모든 설정 CSV(web/selectors/delays/flow/target/excluded)와 `results.csv` 를 파일 다이얼로그로 교체 로드 → 다른 PC 설정을 그대로 이식.
- **내보내기(Export)**: 각 CSV를 `shutil.copy` 로 원하는 위치에 저장(v2 유지).
- **이어하기(Resume)**: `state.json` 기반으로 마지막 `tag_index/post_index` 부터 재개. `results.csv` 의 username 들을 `seen_usernames` 로 선로딩.
- 모든 CSV는 사람이 편집 가능한 평문 → 그대로 메신저/드라이브로 공유.

## 8. 상세 로깅 (메모 #11)

- **UI 로그 탭**: 색상 구분(step=파랑, info=회색, warning=주황, error=빨강) — v2 유지.
- **영속 로그 파일**: `data/logs/run-YYYYMMDD-HHMMSS.log` 에 동시 기록.
  - 각 줄: `[ISO8601] [LEVEL] [step_id] message`.
  - 기록 항목: 각 step 진입/완료, 사용된 셀렉터 priority, 매칭 개수, 적용된 딜레이 값, dedup skip, 필터 탈락 사유, 차단 감지, 예외 트레이스백.
- **진행 표시**: 현재 `tag_index/max_tags`, `post_index/posts_per_tag`, 누적 수집 수, 중복 skip 수를 진행바·라벨로 실시간 표시.

## 9. 코드 변경 요약 (구현 가이드)

### `core/storage.py`
```python
load_web() / save_web(dict)
load_selectors() -> list[dict]      # priority 정렬 포함
load_delays() -> dict[str, (min,max)]
load_flow() / save_flow(dict)
load_target() / save_target(dict)
load_excluded() / save_excluded()                  # v2 유지
append_result(info) / load_results()               # dedup 체크 내장
load_state() / save_state(dict) / clear_state()     # 신규 (state.json)
seen_usernames() -> set[str]                        # results+excluded 합집합
```

### `core/scraper.py` (ScraperThread)
- 생성자: `web, selectors, delays, flow, target, excluded_set, resume_state` 주입.
- `_resolve_selector(step_id)`: priority 순회하며 첫 매칭 요소 반환(없으면 coord 폴백/예외).
- `_human_type(el, text)`: 글자별 딜레이 타이핑.
- `_apply_stealth(driver)`: UA/창크기/webdriver flag 처리.
- `_should_skip(username)`: §6 게이트.
- step 완료마다 `save_state()` 호출.
- 신호 추가: `step_signal(step_id)`, `skip_signal(username)`, `blocked_signal()`.

### `ui/settings_view.py`
- QTabWidget 탭 재편: **웹 / 버튼매핑 / 시간텀 / 플로우 / 타겟 / 제외** (6탭).
- 버튼매핑 탭: 행 추가·삭제·priority 정렬 + **[셀렉터 테스트]**.
- 헤더에 **[설정 불러오기] [설정 내보내기]**.

### `ui/main_window.py`
- `QSystemTrayIcon` + 트레이 최소화.
- **[이어하기]** 버튼(= `state.json` 존재 시 활성).
- 차단 감지(`blocked_signal`) 시 모달 경고 + 일시정지.

### `tests/`
- `test_storage.py`: 신규 5개 설정 파일 round-trip, dedup append, state save/load/clear.
- `test_scraper_utils.py`: `_resolve_selector` priority 폴백, `_should_skip` dedup, `_human_type` 호출 횟수, `_apply_stealth` 옵션 반영.

## 10. Non-Goals (v3 범위 외)
- Google Sheets 연동 (v2에서 제거 — CSV로 대체).
- 인스타 크리덴셜 저장 / 자동 로그인 (사용자 직접 로그인 유지).
- Caption(본문) 키워드 스크래핑 (해시태그 우선, `target.csv:mode` 자리만 예약).
- 프록시/IP 로테이션 (현 단계 미지원 — 핑거프린트 랜덤화까지만).
- 완벽한 봇 탐지 회피 보장 (§5 한계 명시).

## 부록 A — 원본 요구사항 메모 (raw)

> 1. 구글시트 연동하면 저가 개발이 힘들어 질것 같아서 csv로 파일을 공유가능하게 하겠습니다.
> 2. 크롤링할때 인스타 웹의 버튼 위치값을 인식해야하는데 인스타 업데이트나 os에 따라서 혹은 화면 사이즈에 따라서 위치가 변경됩니다. 상대위치로 해도 오류가 발생합니다. 그래서 개별로 상세하게 세팅할 수 있도록 세팅파일을 만들고 csv로 설정파일을 공유할 수 있도록하겠습니다.
> 3. 백그라운드 실행을 가능하게 해서 켜놓고 다른 업무가 가능하도록하겠습니다.
